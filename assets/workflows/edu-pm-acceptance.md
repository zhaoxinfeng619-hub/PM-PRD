# PM功能验收清单工作流

## 输入与目录

读取当前需求的 PRD、原型与相关规则，已有路径直接复用。记录验收对象、PRD 版本、测试环境和产品版本。
输出 `[需求名]/验收清单/[需求名]-验收清单.html`。没有实际测试环境时可以生成清单，所有结果初始为待验收。

## 用例结构

每项具有稳定用例编号、关联功能或规则、优先级、前置条件、测试数据、具体操作步骤、可观察的预期结果。
执行后记录实际结果、截图或缺陷链接、验收人、时间；无证据时不得把“已生成用例”写成“验证通过”。
覆盖主流程、角色权限、适用异常、视觉交互和埋点。PRD 省略异常独立章节时，仍读取详细方案中的边界规则。
每项只验证明确的行为，不使用“功能正常”“体验良好”作为唯一通过标准。

## 统一四态与统计

- 待验收：未执行或被阻塞；阻塞原因另记，不自动跳过。
- 通过：执行结果满足预期，有实际验证记录。
- 未通过：执行结果不满足预期，保留实际结果与缺陷。
- 跳过：不适用或明确暂不验收，必须填写原因。
- 筛选包含全部和上述四态；四态数量合计必须等于用例总数。
- 执行完成率 =（通过 + 未通过）/（总数 - 跳过）；通过率 = 通过 /（通过 + 未通过）。
- 分母为零显示“暂无可计算样本”，同时展示跳过数及原因。不得用跳过推高通过率或宣布全部完成。
- 任意必验项待验收/未通过，或存在未解除的阻塞，都要单列，不自动给出上线通过结论。

## HTML 与持久化

复用 scripts/pm-acceptance.js，不重复实现状态与统计逻辑。HTML 提供 #acceptanceContent 容器与 #acceptanceData JSON 槽位。
JSON 包含 title、version、cases；每项包含 id、module、title、priority、preconditions、data、steps 数组、expected。
可将公共脚本内嵌为单文件交付，业务样式按需求设置。源码 JSON 必须安全转义，不能将用户输入作为可执行脚本拼接。

明暗主题按场景选择；提供四态选择、模块折叠、优先级/状态筛选和实际结果编辑。
localStorage key 包含清单路径及验收版本，按用例编号存储。内容或预期结果变化后，相关用例恢复待验收，旧结果保留为历史。
提供 JSON 导出/导入和便于阅读的汇总，包含版本、统计、实际结果、证据及跳过原因。
导入验证结构与用例编号；版本不同不得覆盖当前结果。说明进度保存在当前浏览器，需要导出传递给他人。

## 自测与交付

至少验证四态切换、跳过原因、零分母、状态筛选、刷新恢复与导出导入；抽查用例能按步骤执行。
报告清楚区分“清单已生成”和“产品实际已验收”，未执行的用例保持待验收。
