# PM需求产出工作流

## 1. 需求确认与交付范围

核对问题背景、目标、用户场景、现有方案、业务规则和参考方向。已有信息直接复用，只追问影响方案的缺口。
需求清晰后简要复述目标、范围、关键规则及成功指标。用户已经明确确认并要求产出时直接继续，不重复问相同问题。
章节裁剪和业务范围变更提前说明；用户明确要求删除或保留的章节直接照办。

复用 [需求名]/，按实际产出创建需求文档、原型、流程图等目录。沟通结论保存在同需求的沟通记录.md。
不以创建了文件夹作为已经确认需求的依据。

## 2. PRD 内容

输出 [需求名]/需求文档/[需求名]-PRD.html。
核心内容保留项目信息、版本记录、需求背景、需求目标、详细方案。其他章节按实际复杂度使用，顺序为：
需求概述 → 业务流程图 → 交互流程图 → 详细方案 → 异常与边界 → 数据埋点 → 时序图 → 上线计划 → 附录。

不存在的章节不留空标题，序号连续。简单修改可以简写核心内容，不强行扩展为完整规划文档。
没有真实基线或排期时写待确认，不编造目标和日期。

### 详细方案

使用四列表格：一级模块、二级功能、原型、描述。同模块可用 rowspan 合并。每个功能行与具体页面状态对应。
描述按以下分块写，编号使用 1、2、3：

| 分块 | 要求 |
|---|---|
| 【页面元素】 | 必需，说明布局、可见文案、数据、控件和入口 |
| 【交互说明】 | 必需，按“操作 → 可观察结果”写 |
| 【功能逻辑】 | 涉及扣减、排序、推荐、权限或状态推进等规则时写 |
| 【边界说明】 | 写当前功能实际涉及的空态、失败、超时、重复操作等 |
| 【数据与内容规则】 | 写展示数据来源、样例口径及排序条件 |
| 【前置条件与权限】 | 写登录、角色、额度、配置等进入条件 |
| 【文案规范】 | 需要精确确认的按钮、提示和弹窗文案 |

详细方案描述列用产品语言，不写 API、数据库或请求参数。埋点和研发向时序图可使用技术名称。
异常独立章节可以省略，但当前功能相关的边界说明仍需覆盖。
同一条业务规则只定义一个权威口径，其他章节引用或保持一致。

## 3. 复用文档组件

先阅读 .agents/references/pm-artifacts.md。默认从 templates/prd-shell.html 生成，复用 scripts/pm-document.js 和 scripts/prototype-export-client.js，不重新手写编辑器和复制组件。

文档必须支持：
- 正文及适用表格编辑、列宽/行高调整、数据行增删，保存后重新打开仍可使用。
- 左正文、右活原型双栏，页面切换、正文滚动联动、缩放与面板宽度调整。
- 一键复制正文和内联图片；可以强制重新生成图片；缺图明确显示位置与数量。
- 保存到明确目标，检查加载时的文件版本并先备份。下载副本与保存原文件分别提示。
- 保存完成后提示让 AI 读取磁盘文件，同步相关产物；不得声称点击按钮已经自动通知或完成同步。

模板内容区和页面目录 JSON 由当前需求生成。业务内容自行排版，公共交互复用组件。
本地服务配置通过 ../../scripts/pm-runtime-config.js 加载；该文件包含本机凭据，不放入公开分享包。

## 4. HTML 原型

输出 [需求名]/原型/[需求名]-prototype.html。每个页面状态采用稳定 hash；无 hash 默认平铺，有 hash 只显示对应页。
页面使用 .device-wrapper > .device[id]，标签写清页面与状态。单页模式隐藏其他 wrapper，不能隐藏包含所有页面的父容器。

- 尺寸按真实终端确定；手机、桌面和大屏分别使用实际比例。
- 配色、字体、图标和组件优先沿用现有产品规范。不能为了视觉调整擅改业务规则。
- CSS 和必要资源本地化。已有本地图标库可以复用，不强制 CDN；确需联网资源时说明离线限制。
- Tab、返回、选择、输入、提交、提示等实际涉及的交互可操作。模拟结果和进度必须标明。
- 同类组件复用渲染与状态逻辑，多页数据使用统一来源。
- PRD 只接受当前预览 iframe 的消息，原型只接受其父窗口的导航指令。

~~~js
// 原型切页后
window.parent.postMessage({type: 'page-changed', page: 'detail'}, '*');
// 原型收到父窗口导航时检查 event.source === window.parent
~~~

表格原型嵌入：

~~~html
<div class="prototype-frame" data-pw="390" data-ph="844">
  <iframe class="prototype-iframe" src="../原型/[需求名]-prototype.html#detail" title="详情页"></iframe>
</div>
~~~

导出入口只保留一个，无需自写截图逻辑：

~~~html
<button id="exportFab" data-export-ui="true">一键导出所有截图</button>
<script src="../../scripts/pm-runtime-config.js"></script>
<script src="../../scripts/prototype-export-client.js"></script>
~~~

用户请求 Pencil 时再读取 .agents/references/pm-pencil.md。普通交付不要求安装可选设计工具。

## 5. 流程图与时序图

需要这些产物时读取 .agents/references/pm-diagrams.md。
业务流程图表达业务逻辑，交互流程图表达页面与跳转，时序图用于研发和测试理解跨组件编排。
图表报错先修复，无法完成时明确说明阻塞和缺失，不能删除图表掩盖问题。
时序图采用可复制 Mermaid 源码块，放在数据埋点后、上线计划前，交付前验证语法。

## 6. 交付、自测与迭代

交付前按实际改动检查：
1. 逐页核对原型与 PRD 的标题、按钮、提示、数据、状态、跳转及 Tab。
2. 运行主路径和重要异常路径；分清模拟交互通过与真实业务已验收。
3. 检查文件链接和本地脚本路径、移动端溢出与宽高比例。
4. 验证正文编辑、合并行增删、保存后重新打开、双栏缩放和对应页面切换。
5. 点击带图复制，在目标文档首次粘贴确认图文保留；无法访问目标文档时说明只验证到浏览器剪贴板。
6. 导出原型和流程图；旧图只有在新一轮全部成功后才替换，个人截图与旧备份不能清空。
7. 报告实际通过、失败和未执行项。不能预填“全部通过”。

每次改动检查版本记录、目标、功能清单、详细方案、权限与异常、埋点、时序、上线计划、原型、流程图和页面目录。只更新受影响位置。
相关验收和数据分析若已经产出，检查是否需要更新其预期结果或指标口径，不自动改写既有验收事实。
变更导致需要补回章节时先说明理由；用户已授权的范围按现有决定执行。

## 7. 会话续接

需要交接时，将已确认决策、当前阶段、产物路径、未解决问题和下一步写到 .handoff/[需求名]-handoff.md，同步 [需求名]/沟通记录.md。
恢复时优先读取交接摘要、必要源文件及相关工作流。复述当前进度后继续，已确认事项不再反复确认。
